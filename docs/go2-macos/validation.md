# Go2 macOS 适配实验记录

记录日期：2026-09-26。此页是经过隐私整理的结果摘要，不附实际相机图像、完整模型日志或数据库。原始证据保留在本地，以下结果不是官方 benchmark，也不是当前在线运行状态。

## 仿真阶段

- 最小空场景：同一中文指令在交换红蓝视觉标记后，Agent 根据新图像分别选择 `y=+0.6` 与 `y=-0.6`，每轮完成 `observe -> move_to -> observe`。指令距离不是精确实测位移。
- 官方公寓场景：点云进入 dimOS VoxelGridMapper / CostMapper / ReplanningAStarPlanner；原生探索移动，累计地图曾达到 51,010 点。定位来自仿真里程计，不是独立 SLAM 成功证据。
- CPU CLIP + Chroma 存储图像/位姿，停止和重启后保留并加载 370 张图像。修复检索排名与各自位姿对应、随机嵌入回退、重复停机丢图和原地转向采样。
- 已探索场景的厨房回访：Agent 用英文语义查询选中历史观察点，经 `following_path` 到 `idle / goal_reached=true`，最终距选中的历史点约 0.20 m，再观察。独立评估距冰箱表面约 1.342 m；真值未发送给 Agent。这不是无历史记忆的自然起点 VLN，也不是精确贴近冰箱。
- DeepSeek 实际图像描述与沙发/餐车 2D 框、原生 `look_out_for` 橱柜识别已测试；3D 投影、可靠跟随、动态避障、语音、多任务成功率未验收。沙发记忆曾首选错误，不能假定语义匹配可靠。
- 原生 Cockpit 中文输入、工具调用和最终答复完成端到端验证。改用 Cockpit 不代表旧 Rerun 抽搐根因已修复，也未证明长时间稳定。

## Go2 EDU 真机阶段

- 使用网线接入；保留 Mac Wi-Fi 的互联网路由。Jetson 未发现无线网卡，不推断整机没有 Wi-Fi；没有配置机器人 Wi-Fi。
- WebRTC 相机/里程计/电量接通；一次授权视觉问答使用 1280x720 实际画面，相机约 14 FPS，模型请求 HTTP 200，中文最终回答完成。没有发送运动命令。
- WebRTC 点云通道未收到帧，而机器人原有 ROS 2 雷达 topic 有约 13 Hz 数据。因此采用 SSH 临时只读 ROS 2 订阅器，约 3 Hz 发送 XYZ 至 Mac。Jetson 未安装依赖、未写程序文件、未改系统服务。
- 去畸变点云存在每帧约 10,000 条全零填充；过滤后示例为 226-266 个有效点，而非上万真实观测。没有把零点当成地板、没有生成假地面或强行清空脚下未知格。
- dimOS 原生体素地图和 5 cm 代价地图在 Cockpit 显示；某次约有 1,690 个已知格。机器人实际起点原始代价为 -1，膨胀代价为 100，向前 0.5 m 预览正确返回 `INVALID_STATE`，未运动。
- 实际地图两个已知格之间的 A* smoke 仅为 5 cm 算法测试，不是从机器人起点规划的可行路线。不能称为真机导航/VLN 已成功。
- 用户确认机器狗站立；覆盖不足不能归因于趴着。仍需获取连续环境覆盖、验证动态坐标一致性、实测 footprint，再逐项验证路径、控制和安全停止。
- 曾遇本地回环连接超时和 TLS 环境代理问题。当前真机入口采用 Zenoh，并仅在进程设置 loopback/DeepSeek 的 NO_PROXY；没有改系统代理或机器人配置。此对照不等于已证实底层故障根因。
- 换电前已停止本机 dimOS 服务和只读 SSH 主连接。后续启动必须重建地图/位姿，不把缓存当实时数据。

## 对后续功能的判断

打通相机、点云、里程计和通信是必要基础，不是所有功能可用的充分条件。语义目标匹配、地图覆盖/坐标同步、真实路径跟踪、动态避障、失败恢复及现场安全都需要独立验收。当前只读组合刻意不加载真机运动控制，也不套用仿真空间记忆。

## 2026-09-27 重连测试

- 重建已认证 SSH 会话后，只读 Cockpit、约 14 FPS 相机、ROS 点云和代价地图恢复。一次授权自然语言请求完成真实电量/感知状态查询、视觉描述及向前 0.3 m 路径预览；预览因实际起点 footprint 未被可通行地图覆盖而拒绝，未发送运动命令。
- 对比雷达来源：一次采样中原始 cloud 约 1,277 个有效点、81 个不同的 5 cm XY 格；cloud_base 和去畸变 cloud 各约 149 个有效点。不能以原始点数增加推断地图完整，也不能把雷达坐标直接冒充世界坐标。多个声明存在的地图 topic 在 8 秒窗口内未收到数据。
- 随后相机/里程计/点云同时变旧，两个机器人端口不可达。旧地图预览正确拒绝 stale 数据。用户解锁后重试仍未恢复；有线链路 active、Wi-Fi 默认路由正常不等于机器人服务在线。该记录不是当前在线状态，也不证明解锁导致断线。
- 增加只读启动预检及 ROS 桥启动前检查，SSH 检查限定时间、保持主机指纹校验，不保存密码。不自动重连、不自动站立、不开放运动，也不清除未知起点。

### 近场点云与趴姿历史对照

- 后续连接恢复。对照单帧与累计地图，旧会话 15,757 个累计点中近场 594 个；当前单帧 303 个、近场 256 个。保持站立后完整重建只读栈，示例新地图 2,474 个、近场 284 个，但新单帧仍有 260 个近场点，起点仍为未知。采样时长不相同，不能把数量下降当成算法改善或唯一病因证据；也不能把这些点全部认定为自反射。
- 用户确认静止。约 12 秒、225 次位姿采样，水平位置变化约 1.05 cm、yaw 变化约 0.125 度，提示当前里程计存在静止漂移；未完成独立定位真值验证，不能据此断言完整 SLAM 根因。
- 修正高度代价算法的 Sobel 邻域有效性：计算使用 3×3 邻域，旧有效性检查只检查十字四邻域，缺失斜对角高度以零进入计算，导致相同平地仅改变世界 Z 原点就从 cost 0 变成 94。现在缺失梯度邻域保留未知，不假设地面或强行清障。
- 同一份 9,207 点真实累计云，在其余算法/参数保持一致时，391 个观测不足边缘格从已知改为未知，其中 17 个原标 cost 100；没有将这些高代价格改成自由格。真实台阶回归保持障碍分类。这是边界误判修复，不是地面分割、自体滤波或导航已成功的证据。
- 高度边界、全新地图会话、原生规划护栏、只读连接及预检聚焦回归 **61 passed**；有 3 个可选 pytest 配置警告和一次启动期 subprocess ResourceWarning。新增测试 Ruff 通过；原 occupancy 文件已有 3 条 Ruff 诊断仍保留。未装 mypy，未运行依赖实际数据 golden 图的 self-hosted 全量测试。
- 修复接入新只读会话后相机约 14 FPS、点云/地图数据新鲜，向前 0.3 m 仍因未知起点拒绝。另一次 6 秒 ROS 订阅窗口中 robot_odom 收到 1,169 帧、水平变化约 5 mm；uslam frontend/localization 与 lio_sam mapping odometry 均为 0 帧。在当前 Jetson 进程和所用 ROS 环境中未发现可运行的 SLAM 服务/包；不据此断言整机没有 SLAM 能力。没有启动额外机载服务、安装包、修改坐标系或保存真机图像。
